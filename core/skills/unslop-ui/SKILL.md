# unslop-ui

差分が持ち込んだ AI っぽさを、プロジェクトのデザインシステムと既存の画面に合わせて取り除く。AI っぽさが無ければ、何も変えない。

## 決める順

ルールが食い違ったら、次の順で決める。

1. プロジェクトのデザインシステムと既存の画面
2. 依頼
3. このスキルの既定（[references/catalog.md](references/catalog.md)）

部品、言葉、置き場所は、既存の画面の同じ役割のものに合わせる。新しく作らない。

## 消さないもの

次のものは AI っぽく見えても消さない。直すなら【移す】か【書き直す】にする。

- フォームのラベル、必須と任意の表示、入力した後のエラー文
- アイコンだけのボタンのアクセシブルな名前
- デザインシステムが求める説明の枠と定型文
- 色だけで示した情報の、凡例やアクセシブルな名前
- 利用者が推測できない書式の条件（文字種、桁数、日付の形）

## 範囲

差分が足した行と変えた行だけを見る。画面全体を見るのは、画面全体のレビューを頼まれたときだけにする。差分の外で同じ型を見つけたら、直さずに報告の「残したもの」に書く。

## 手順

1. 既存を見る。同じ役割の画面と部品を探し、部品、言葉、置き場所を控える。デザインシステムの文書があれば読む。
2. 検査のスクリプトを走らせる。

   ```bash
   node <このスキルのフォルダ>/scripts/check-ui.mjs --base <基点>
   ```

   - 基点はブランチの分岐元（`main` など）にする。コミットしていない変更だけなら `HEAD` にする。
   - ファイルかフォルダを渡すと、差分に関係なくその全体を見る。
   - 見るのは `.tsx` `.jsx` `.vue` `.html` と i18n の `.json` だけである。ほかのファイルは目で見る。
   - 出力は候補で、直す合図ではない。終了コードは候補の数によらず0になる。0件を目指さない。
3. 要否を確かめる。差分が足した要素ごとに、利用者がそれを使う場面を1つ挙げる。挙げられないものは消す（need-unrequested）。
4. 下の表の観点で確かめる。各ルールの症状、直し方、例外、根拠はカタログにある。
5. 直す。直し方は次のどれかにする。
   - 【消す】重複している要素や文、利用者が使わない要素や文を消す。
   - 【移す】説明や状態を、それが指す対象の隣へ移す。
   - 【枠に入れる】デザインシステムが用意した場所に入れる。説明の枠、既存の部品、間隔や色のトークンを使う。
   - 【書き直す】同じ場所のまま、文言か動きを書き直す。
6. 描画できるなら、ヘッドレスのブラウザでスクリーンショットを撮って見直す。広い幅と 390px 前後の幅で撮り、拡大して線と中心を比べる。撮り直しは3回までにする。
7. 下の形で報告する。

## 観点

| 観点 | 見るところ | 合格 | 主な直し方 | 例外 |
|---|---|---|---|---|
| 近接 | 補足、状態の表示、通知と、それが指す対象との距離 | 関係が近さ、まとまり、名前でわかる。言葉で補っていない | 【消す】【移す】 | 入力した後のエラー文。推測できない書式の条件 |
| 整列 | 拡大したスクリーンショットの、アイコンと文字の中心、並んだ要素の線、字下げ | ずれが無い。狭い幅でも重ならず、はみ出さない | 【枠に入れる】既存の揃え方と間隔のトークン | なし |
| 反復 | 既存の画面の、同じ役割の部品、言葉、置き場所 | 同じ役割は同じ部品、同じ動詞、同じ場所にある。状態でレイアウトが変わらない | 【枠に入れる】 | デザインシステムが別の部品を指定しているとき |
| コントラスト | 囲み、カード、飾り（グラデーション、色線、きらめき）、目立たせた操作の数 | 差が大きさ、太さ、余白で付いている。主な操作が1つだけ目立つ | 【消す】【枠に入れる】 | デザインシステムのカード。ブランドの色 |
| 文言 | 補足、プレースホルダー、見出しの下の説明、エラー、確認、空の状態の文言 | 1つのことを1回、利用者の言葉で書いている。カタログの「出してよい条件」を満たす | 【消す】【枠に入れる】【書き直す】 | ラベル。エラー文。デザインシステムの定型文 |
| 操作 | 操作の後の通知、確認、動き、開いた入力欄のフォーカス、待ち時間の表示 | 画面の変化で結果がわかるなら通知しない。取り消せる操作に確認を出さない。待っていることが見える | 【消す】【移す】【書き直す】 | 見えない結果の通知。取り消せない操作の確認 |

## 引きすぎない

引くのは情報で、作りの厚みではない。次のときは変えない。

- AI っぽさが無い。
- デザインシステムか依頼がそう決めている。
- 利用者がその場で要る情報である。

直した後に、カタログの「引きすぎ」の型に当たっていないかを確かめる。書式の条件を消していないか、余白と階層まで削って平板になっていないか、待っている間の表示を消していないかを見る。

## 任せる先

- 見た目の方向を新しく決めるときは、frontend-design スキルに任せる。
- アクセシビリティの監査は accessibility-review スキルに任せる。このスキルではアクセシビリティを下げていないことだけを確かめる。
- ヘルプページやリリースノートなど、段落の文章は yomiyasu スキルで推敲する。UI の文字列（コンポーネントの中の文字、i18n のファイル）はこのスキルで扱う。

```markdown
### 直したもの
- <ルールの ID> <ファイル:行> <前> → <後>。<理由を1文>

### 残したもの
- <ルールの ID> <ファイル:行> <残した理由（デザインシステム、アクセシビリティ、利用者に要る、差分の外）>

### 確かめたいこと
- <デザインシステムにも既存の画面にも決まりが無く、こちらで選んだこと>

### 確かめたこと
- check-ui.mjs: 候補 <n> 件、うち直した <m> 件
- スクリーンショット: <撮った幅> ／ <撮らなかった理由>
- 実行しなかった確認: <あれば>
```
